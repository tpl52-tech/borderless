Borderless
Right now your "environment" IS Expo Go pointed at the one Supabase/Firebase project. To verify a merged ticket, QA pulls main, runs it in Expo Go, and checks against the real backend — no deploy, no staging. The backend is a single shared project, so tests do write to the real DB (safe enough: RLS + throwaway accounts + seed data). The app only leaves Expo Go at the first EAS build (Phase 4, when Stripe's native SDK forces it) → TestFlight / internal. App Store / Play submission is a post-Phase-4 launch milestone, and EAS Update (OTA for JS-only changes) exists only once you have EAS builds. Before that, pulling the repo IS the update.
